# TaskFlow Pro — 需求分析文件

> 文件版本：v1.0 | 建立日期：2026-06-29

---

## 1. 系統目標

TaskFlow Pro 是一套面向中小企業（5～100 人團隊）的企業級任務管理系統，目標如下：

- **提升任務透明度**：讓每位成員隨時掌握任務狀態與截止日期，減少資訊落差。
- **強化責任歸屬**：透過任務指派與 Audit Log，明確記錄誰做了什麼、何時做的。
- **保障資料安全**：以 JWT 驗證確保只有授權使用者才能存取系統；RBAC 權限模型確保角色邊界清晰。
- **支援多層級協作**：Admin 統管全局、Manager 主導專案執行、User 專注個人任務，三層角色分工明確。

## 2. 使用者角色與權限

### 2-1 角色定義

| 角色 | 說明 |
|------|------|
| **Admin** | 系統管理員。負責使用者帳號管理與系統監控，可查閱所有資料與稽核紀錄。 |
| **Manager** | 專案/團隊主管。負責建立任務、指派工作給 User，並追蹤團隊整體進度。 |
| **User** | 一般成員。只能查看與更新自己被指派的任務。 |

### 2-2 權限矩陣

| 功能 | Admin | Manager | User |
|------|:-----:|:-------:|:----:|
| 建立使用者帳號 | ✅ | ❌ | ❌ |
| 修改任意使用者資料 | ✅ | ❌ | ❌ |
| 停用/啟用帳號 | ✅ | ❌ | ❌ |
| 查看所有使用者列表 | ✅ | ✅（限自己團隊） | ❌ |
| 建立任務 | ✅ | ✅ | ❌ |
| 指派任務給任意成員 | ✅ | ✅（限自己團隊） | ❌ |
| 刪除任何任務 | ✅ | ✅（自己建立的） | ❌ |
| 查看所有任務 | ✅ | ✅（團隊任務） | ❌ |
| 查看自己的任務 | ✅ | ✅ | ✅ |
| 更新自己任務的狀態 | ✅ | ✅ | ✅ |
| 查看 Audit Log | ✅ | ❌ | ❌ |
| 修改自己的個人資料 | ✅ | ✅ | ✅ |

## 3. 使用者故事

### 3-1 Admin 使用者故事

1. 作為 **Admin**，我想要**建立新使用者帳號並設定其角色**，以便快速將新進員工加入系統並賦予適當權限。

2. 作為 **Admin**，我想要**停用離職員工的帳號**，以便確保前員工無法繼續存取公司任務資料，保障資料安全。

3. 作為 **Admin**，我想要**查看所有使用者的列表與帳號狀態**，以便掌握系統內所有成員的帳號健康狀況。

4. 作為 **Admin**，我想要**查看完整的 Audit Log 稽核紀錄**（包含誰在何時建立、修改、刪除了哪筆資料），以便在發生爭議或安全事件時進行追查。

5. 作為 **Admin**，我想要**查看系統中所有任務的狀態**，以便從全局視角監控整體業務執行情形。

6. 作為 **Admin**，我想要**重設任意使用者的密碼**，以便協助忘記密碼的員工恢復帳號存取。

### 3-2 Manager 使用者故事

1. 作為 **Manager**，我想要**建立新任務並填寫標題、說明、優先序與截止日期**，以便清楚定義工作內容與交付期限。

2. 作為 **Manager**，我想要**將任務指派給特定的 User**，以便明確分工、讓成員知道自己的責任範圍。

3. 作為 **Manager**，我想要**查看我建立的所有任務與其目前狀態**，以便即時掌握團隊的整體進度，提早發現阻塞點。

4. 作為 **Manager**，我想要**修改任務的優先序或截止日期**，以便因應業務變化靈活調整工作排程。

5. 作為 **Manager**，我想要**將任務重新指派給不同的 User**（例如成員請假時），以便確保任務不因人員異動而停擺。

6. 作為 **Manager**，我想要**將已不需要的任務刪除**，以便保持任務列表整潔，避免成員被過時資訊干擾。

### 3-3 User 使用者故事

1. 作為 **User**，我想要**查看所有指派給我的任務清單**，以便清楚知道自己目前有哪些待辦工作。

2. 作為 **User**，我想要**將任務狀態從「待辦」更新為「進行中」或「已完成」**，以便讓 Manager 即時了解我的工作進度，無需開口回報。

3. 作為 **User**，我想要**查看任務的完整詳情**（說明、截止日期、優先序），以便了解工作的全貌與期望結果，減少來回確認。

4. 作為 **User**，我想要**依截止日期排序查看我的任務**，以便優先處理最緊急的工作，避免逾期。

5. 作為 **User**，我想要**修改自己的個人資料**（顯示名稱、密碼），以便維護帳號資訊的正確性與安全性。

## 4. 功能清單與優先順序

### P1 — 第一階段必做（核心功能，系統上線必備）

#### 4-1-1 使用者認證系統
- [ ] 使用者登入（Email + 密碼，回傳 JWT Token）
- [ ] 使用者登出（前端清除 Token）
- [ ] JWT Token 驗證 Middleware（保護所有需認證的路由）
- [ ] 密碼以 bcryptjs 雜湊儲存

#### 4-1-2 使用者管理（Admin）
- [ ] 建立使用者（Admin 操作，設定 Email、密碼、顯示名稱、角色）
- [ ] 查看使用者列表（分頁）
- [ ] 查看單一使用者詳情
- [ ] 停用 / 啟用使用者帳號

#### 4-1-3 RBAC 權限控制
- [ ] 角色 Middleware（驗證請求者是否有對應角色的操作權限）
- [ ] Admin / Manager / User 三層角色邊界實作

#### 4-1-4 任務管理
- [ ] 建立任務（標題、說明、優先序、截止日期、指派對象）
- [ ] 查看任務列表（依角色過濾：Admin 看全部、Manager 看團隊、User 看自己）
- [ ] 查看任務詳情
- [ ] 更新任務狀態（todo → in_progress → done）
- [ ] 更新任務資料（標題、說明、優先序、截止日期、指派對象）
- [ ] 刪除任務

#### 4-1-5 個人帳號
- [ ] 查看自己的個人資料
- [ ] 修改顯示名稱
- [ ] 修改密碼（需驗證舊密碼）

#### 4-1-6 Audit Log 稽核紀錄
- [ ] 自動記錄關鍵操作（建立 / 修改 / 刪除任務、帳號異動）
- [ ] Admin 可查看 Audit Log 列表（含操作者、時間、動作、對象）

---

### P2 — 第二階段（使用者體驗強化）

#### 4-2-1 任務篩選與搜尋
- [ ] 依狀態篩選任務（todo / in_progress / done）
- [ ] 依優先序篩選任務（low / medium / high）
- [ ] 依截止日期範圍篩選
- [ ] 關鍵字搜尋任務標題

#### 4-2-2 儀表板統計
- [ ] 個人任務統計（各狀態數量、即將到期任務）
- [ ] Manager 團隊任務統計（完成率、進行中數量）
- [ ] Admin 全局統計（總任務數、總使用者數）

#### 4-2-3 任務排序
- [ ] 依截止日期排序
- [ ] 依優先序排序
- [ ] 依建立時間排序

#### 4-2-4 分頁功能
- [ ] 任務列表分頁（預設每頁 20 筆）
- [ ] Audit Log 分頁

---

### P3 — 第三階段（進階功能，之後再說）

#### 4-3-1 通知系統
- [ ] 任務截止日前 N 天自動提醒
- [ ] 被指派新任務時的系統通知
- [ ] 任務狀態變更時通知相關人員

#### 4-3-2 專案管理
- [ ] 建立專案（分組管理多個任務）
- [ ] 任務關聯至專案
- [ ] 專案進度追蹤（依子任務完成率計算）
- [ ] 里程碑設定

#### 4-3-3 報表匯出
- [ ] 匯出任務清單為 CSV
- [ ] 匯出 Audit Log 為 CSV
- [ ] 任務統計報表 PDF 匯出

#### 4-3-4 使用者管理進階
- [ ] Admin 修改任意使用者資料
- [ ] Admin 重設任意使用者密碼
- [ ] 使用者帳號搜尋

#### 4-3-5 任務進階功能
- [ ] 任務留言 / 評論
- [ ] 任務附件上傳
- [ ] 任務子任務（Sub-task）
- [ ] 任務標籤（Tag）

#### 4-3-6 系統設定
- [ ] 全局系統設定（Admin 操作）
- [ ] Docker 容器化部署

## 5. 不在本次範圍的功能

以下功能明確**不納入** P1、P2 開發範圍，以控制專案複雜度：

| 功能 | 排除原因 |
|------|---------|
| 即時通知（WebSocket / SSE） | 技術複雜度高，課程重點不在即時通訊 |
| 電子郵件寄送（SMTP） | 需外部服務整合，超出目前範圍 |
| OAuth 第三方登入（Google / GitHub） | 非核心認證需求，後期可擴充 |
| 行動裝置 App（iOS / Android） | 本系統為 Web 應用，不含原生 App |
| 多語系 i18n | 目前僅需支援繁體中文介面 |
| 進階圖表視覺化（Chart.js 等） | P3 儀表板功能再評估 |
| 多租戶（Multi-tenant）架構 | 超出中小企業單一部署情境 |
| 資料備份與還原介面 | 由系統管理員手動處理資料庫檔案 |
